```java
При отправке метрики в неприменимые сначала уходит отдельный запрос POST .../applicability-requests. Он успешно создаёт заявку и переводит метрику в состояние неприменимости — эта операция уже сохраняется в БД.

После этого фронт дополнительно отправляет POST .../metrics/value на сохранение значений метрик. Если в payload этого запроса всё ещё присутствует та же метрика, которую только что отправили в неприменимые, backend уже видит по ней активную заявку и возвращает Metric unlink.

Поэтому получается ситуация:

Заявка на неприменимость успешно сохранилась.

Следующий запрос на сохранение значений упал с Metric unlink.

Пользователь видит сообщение об ошибке, хотя первое действие фактически уже выполнено.

Нужно проверить в Network payload упавшего запроса .../metrics/value: присутствует ли там metricId той метрики, которую непосредственно перед этим отправили через .../applicability-requests.

Если присутствует, то причина подтверждается: фронт после успешной отправки метрики в неприменимые продолжает передавать её в запросе сохранения значений. Такую метрику нужно исключать из последующего metrics/value.

Это отдельный сценарий от исправления периода возобновления метрики — здесь backend корректно блокирует сохранение значения для метрики, которая только что перешла в PENDING.
```
