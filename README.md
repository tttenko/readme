При смене режима работы инициативы сейчас физически удаляется initiative_metric_type. Но если по этому режиму уже есть initiative_metric_assignment, БД не даёт удалить запись из-за FK.

По модели initiative_metric_assignment — постоянная связь, а связанные request/history должны сохраняться.

Какое поведение ожидается?

Запрещать удаление режима, если по нему уже есть история неприменимости метрик, и возвращать контролируемый 400.

Разрешать удаление режима, но тогда придётся удалять связанные assignment/request/history, то есть история по метрикам будет потеряна.

Я бы предложил первый вариант — возвращать 400, так как он не нарушает текущую модель хранения истории.
